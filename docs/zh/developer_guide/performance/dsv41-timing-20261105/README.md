# slot-arena 与 DSpark staging 候选耗时拆解

统计日期：2026-11-05。本文仅离线读取已归档记录，没有启动测试或恢复优化任务。所有钟表时间均为北京时间（Asia/Shanghai）。

## 口径与边界

- 性能测试为 B1、B2 两次独立服务；每次按 C1/C4/C16/C32 各跑一波预热和一波正式请求。每次共 53 条预热、53 条正式请求。预热 8192/32 token，正式 8192/1024 token。
- 精度为单独服务，GSM8K 300 题、并发 32、无预热、每题一次，输出上限 4096 token。
- 总耗时截至停止命令返回，包含服务间间隔；不包含此前代码开发、算子编译、L0 组件测试，也不包含停止后的归档下载、独立复算和提交。因而它是服务测试流程耗时，不是整个研发周期。
- 已有独立起止时间的命令直接计时；命令之间的时间列为“未单独计时的核验、编排及等待”。不能全部解释为空闲，也不能全部解释为模型加载或图编译。
- slot-arena B1 未找到独立启动命令起止记录，以 status.started_at 为起点；其他轮以启动命令起点计时。该缺口不靠后续轮均值补齐。
- 原聊天中的 44.2/49.5、65.3/70.1 分钟为四舍五入值，并用服务 released_at 作终点。本文优先用精度更高的停止命令返回时间，因此有约 1～2 秒差别。
